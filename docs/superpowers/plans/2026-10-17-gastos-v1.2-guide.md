# Gastos.io v1.2 Guided Tour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a 5-step coach-mark tour on Home (dimmed screen, spotlight, swipe demos the user performs), shown once after install/update and replayable from Settings.

**Architecture:** A `GuideController` in `AppContainer` holds the current step (StateFlow). Home targets report their root-coordinate bounds into a `GuideTargets` holder; a `CoachOverlay` composable draws the scrim with a cutout, the bubble, and the animated hand. Home runs in tour mode while a step is active (input blocked except the step's swipe). Seen state is `AppPrefs.guideSeenVersion`.

**Tech Stack:** unchanged (Kotlin 2.0.21, Compose BOM 2024.12.01, DataStore, Robolectric). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-17-gastos-v1.2-guide-design.md`

## Global Constraints

- **No Claude attribution** in commits, PRs, or files. Plain messages, local git identity.
- Step text verbatim: (1) "Enter the amount of your expense" (2) "You can change which payment method you used for this expense" (3) "Then, you can choose from a set of expense types" (4) "You can also specify what you bought (ex: Jollibee or MTG Cards)" (5) "Finally, keep track of your expenses history here!"
- Counter "N of 5"; buttons "Skip", "Next", last step "Done"; swipe steps have no Next.
- Tour never saves an expense; only Next/Done/Skip and the step's swipe work during the tour.
- Show automatically when `guideSeenVersion < 1` (fresh install and v1.1 upgrade); mark 1 on Skip/Done/ON_STOP. Replay from Settings does not touch the pref.
- Theme colors via `GastosTheme.colors` (bubble = surface/fg, glow = accent, buttons use accent/onAccent).
- versionName 1.2.0, versionCode 3, same release key.

## Review Focus

1. **No accidental saves** — during the tour, numpad/Enter/text box/menu/list icon do nothing. Pinned in Task 2 (VM/controller test + tour-mode guard).
2. **Stuck tour** — every step has Skip; leaving the app ends the tour and marks it seen. Pinned in Task 1.
3. **Wrong-axis swipe** — does not advance; right-axis swipe advances even with one method/label. Pinned in Task 1.
4. **Replay doesn't reset seen** — Settings replay leaves `guideSeenVersion` at 1. Pinned in Task 1/3.
5. **Bubble off-screen** — bubble placed above/below the cutout, whichever has room, clamped inside the screen. Pinned in Task 2 (pure placement test).

  - `class GuideController(private val prefs: AppPrefs, private val scope: CoroutineScope)`: `val step: StateFlow<GuideStep?>`; `fun start()` (→ AMOUNT); `fun next()` (non-swipe steps only; on last step = finish); `fun onSwipe(axis: HomeSwipe.Axis)` (advances only when it matches current step's axis); `fun skip()`; `fun finish()`; `fun onAppStopped()` (if active → finish).   - `AppContainer.guide: GuideController` (uses app scope).

### Task 2: Coach overlay and Home integration

**Files:**
- Create: `ui/guide/GuideTargets.kt`, `ui/guide/CoachOverlay.kt`, `ui/guide/CoachLayout.kt` (pure geometry)
- Modify: `ui/home/HomeScreen.kt` (register targets, tour mode, swipe hook), `ui/Nav.kt` or `MainActivity.kt` (auto-start on Home + ON_STOP hook)
- Test: `app/src/test/java/io/gastos/app/ui/guide/CoachLayoutTest.kt`, extend `HomeViewModelTest.kt` or a new test for the tour-mode guard

**Interfaces:**
- Consumes: `GuideController.step/next/skip/onSwipe/onAppStopped/startIfUnseen`, `HomeSwipe.decide`, theme colors.
- Produces:
  - `enum class GuideTarget { NUMPAD, SWIPE_AREA, DESCRIPTION, HISTORY_ICON }`; `GuideStep.target` mapping (AMOUNT→NUMPAD, METHOD/LABEL→SWIPE_AREA, DESCRIPTION→DESCRIPTION, HISTORY→HISTORY_ICON).
  - `class GuideTargets { fun set(t: GuideTarget, r: Rect); fun get(t): Rect? }` exposed via a CompositionLocal or passed down; `Modifier.guideTarget(t)` using `onGloballyPositioned { boundsInRoot() }`. NUMPAD target = union of numpad grid and Enter button bounds (one rect).
  - `object CoachLayout { fun cutout(target: Rect, paddingPx: Float): Rect; fun bubbleTop(cutout: Rect, bubbleHeight: Float, screenHeight: Float, marginPx: Float): Float }` — below the cutout if it fits, else above; clamped to [margin, screenHeight - bubbleHeight - margin].
  - `@Composable fun CoachOverlay(step: GuideStep, targets: GuideTargets, onNext: () -> Unit, onSkip: () -> Unit)` — full-screen (edge-to-edge) Canvas scrim black ~65% with `BlendMode.Clear` rounded cutout (radius 16dp) + accent glow stroke; bubble (surface bg, fg text, "N of 5", Skip text button, Next/Done filled button with accent/onAccent; no Next on swipe steps); animated hand icon looping across the cutout (horizontal for METHOD, vertical for LABEL), static with arrows when `ANIMATOR_DURATION_SCALE == 0`; consumes all pointer input except inside the cutout on swipe steps; step transitions animated ~250ms.
  - Home tour mode: when `step != null`, numpad keys, Enter, text field (readOnly + not focusable), mic, list icon and overflow menu do nothing; starting the tour clears focus/hides keyboard. `SwipeArea` additionally reports the decided axis to `guide.onSwipe(axis)` (in addition to the normal swipe action). The existing accessibility custom actions also call `guide.onSwipe`.
  - Auto-start: when Home first composes, call `guide.startIfUnseen()` once. ON_STOP of the activity → `guide.onAppStopped()`.
