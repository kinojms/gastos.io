# Gastos.io v1.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On both Android and the PWA, ship in-app feedback (sent to the owner's Telegram through a Cloudflare Worker) and swipe-left Edit/Delete on expense rows, with a one-time peek hint and a 6th tour step.

**Architecture:**
- **Relay:** a tiny Cloudflare Worker in `feedback-relay/` holds the bot token as a secret. Its validation and formatting are pure functions with tests.
- **Feedback URL:** both apps read the relay URL from one committed file, `config/feedback-url.txt`. The feedback entry stays hidden while it's blank.
- **Swipe logic:** the snap and direction-lock rules are pure functions, tested on each platform. The row UI is a thin layer on top.
- **Tour:** gains a step plus a version-2 rule (returning users see only the new step).

**Tech Stack:**
- Android: Kotlin/Compose (`AnchoredDraggable` or `pointerInput`), OkHttp, JUnit/Robolectric, MockWebServer.
- PWA: Svelte 5/TS, Vitest, Playwright WebKit.
- Relay: Cloudflare Workers (`wrangler`), TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-17-gastos-v1.4-design.md` (binding). Earlier specs and the existing code are the source of truth for anything it doesn't restate.

## Global Constraints

- No Claude attribution in commits, files or release notes (CLAUDE.md). No `Co-Authored-By` lines.
- Version **1.4.0** everywhere: Android versionCode 5, `web/package.json` 1.4.0.
- The Telegram token and chat ID live **only** in Worker secrets. They never go in the repo, the APK or the web bundle.
- Every create/update/delete confirms. Feedback send confirms with "Send this feedback?", confirm text "Send".
- Feedback types, in this order: `Suggestion`, `Bug report`, `Question`, `Something else`. Message max 2000 characters, contact max 100.
- Message header: `[FEEDBACK - Gastos.io]`.
- Swipe actions: two 72 dp/px buttons. Edit = pen icon on `surface2`; Delete = trash icon on `danger` with a white icon. Accessible names are "Edit" and "Delete".
- New tour step copy, verbatim: `In your history, swipe an expense left to edit or delete it`.
- Commands:
  - Android: `./gradlew testDebugUnitTest lintDebug assembleDebug`.
  - Web, from `web/`: `npm run check && npm test && npm run e2e`.
  - Relay, from `feedback-relay/`: `npm test`.
- npm installs use the public registry. Add `registry=https://registry.npmjs.org/` in `feedback-relay/.npmrc`, as `web/.npmrc` does.
- Work on a branch `v1.4`. Ask the owner before pushing, deploying the Worker or publishing a release.

## Review Focus

1. **A vertical scroll that starts on a row must scroll the list and never open the row.** Test the direction lock in both platforms' swipe-logic tests (Tasks 4 and 6).
2. **HTML or Markdown in feedback text** (`<b>`, `&`, `<script>`) must show literally in Telegram and must not break the message. Escape test in Task 1.
3. **Network down or the relay returns 502 or times out:** an inline error appears, the typed text stays, and there's no crash (especially Android coroutine exceptions). Tests in Tasks 3 and 5.
4. **Returning v1 users** (`guide_seen_version == 1`) see only step 6, once, and Show guide still replays all 6. Tests in Task 7.
5. **Deleting from a swipe while the peek hint or another open row is animating** must delete the right expense (keyed by id), and the open-row state must clear. Tests in Tasks 4 and 6.
