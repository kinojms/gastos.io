# Gastos.io v1.4 — Feedback and swipe actions

Date: 2026-10-17
Builds on: v1.3 (Android `app/`, iPhone PWA `web/`; spec `2026-10-17-gastos-pwa-design.md`). Everything there still holds. Both features ship on **Android and the PWA**, which look and behave the same.

## Intent

1. Let friends and family send feedback (ideas, bugs, questions) from inside the app, with no email app involved. The owner receives each one instantly as a Telegram message.
2. Make editing and deleting expenses faster and more discoverable. Swiping a row left reveals Edit and Delete, like Spotify's song options. A one-time peek and a new tour step teach it.

## Goals

- Settings → **Submit feedback** opens a feedback screen. Sending posts to the owner's Telegram chat through a relay the owner controls.
- Expense rows can be swiped left to reveal **Edit** (pen icon) and **Delete** (trash icon).
- Version **1.4.0** on both platforms (Android versionCode 5).

## Non-goals

- Replies inside the app, a feedback history, attachments or screenshots.
- An offline queue for feedback (the user retries).
- Swipe actions on anything other than expense rows (not the Days tab's day rows, not the Month bars, not the Labels and Payment methods lists).
- Keypad swipes on Home (decided by owner: swipes stay in the middle area only).

## Anti-goals

- The Telegram bot token must never appear in app code, the APK, the web bundle or the public repo.
- No expense data, labels or backup info leaves the phone with feedback.
- Swipe gestures must not make scrolling the list or tapping a row worse. A vertical scroll never opens a row.
- Deleting must still confirm (the CRUD confirm rule).

## 1. Submit feedback

### Screen (both platforms)
- Reached from Settings: a new NavRow **"Submit feedback"** placed above "Show guide". Title "Submit feedback". *(placement: my call)*
- Fields, top to bottom:
  - **Type** dropdown: `Suggestion` (default), `Bug report`, `Question`, `Something else`. *(The owner asked for Suggestion / Bug report / Comments "or something else"; these four are my call.)*
  - **Message**: multi-line, required, placeholder "Tell us what's on your mind…", max **2000** characters, with a live counter "123 / 2000".
  - **Your name or contact (optional)**: single line, max **100** characters, hint "So we can get back to you".
  - **Send** button, disabled while the message is blank (after trimming) or a send is in progress.
- Send → confirm popup **"Send this feedback?"** (confirm text "Send"). *(per the CRUD confirm rule; my call)*
- Success → toast "Thanks! Your feedback was sent." The form clears and the screen closes (back to Settings).
- Failure → an inline error under the button. The typed text is kept.
  - No connection: "No internet connection. Try again when you're online."
  - Anything else (relay error, non-2xx, timeout after 15 s): "Couldn't send feedback. Try again later."

### What's sent (app → relay)
`POST {FEEDBACK_URL}` with `Content-Type: application/json`:
```json
{ "type": "Bug report", "message": "…", "contact": "…or empty", "appVersion": "1.4.0", "platform": "Android" }
```
- `platform` is `"Android"` or `"iPhone"`. The PWA sends `"iPhone"` when `installState() !== 'other'`, else `"Web"`.
- Text is trimmed before sending. An empty contact is sent as `""`.
- `FEEDBACK_URL` is the deployed Worker URL. It isn't secret. *(my calls)*
  - **One source:** a committed one-line file `config/feedback-url.txt`. Gradle reads it into `BuildConfig.FEEDBACK_URL`, and Vite reads it into `__FEEDBACK_URL__` via `define`. A missing or blank file gives `""`.
  - **Guard:** while the URL is blank, the "Submit feedback" row is hidden on both platforms, so nothing ships broken before the relay exists.

### Relay (Cloudflare Worker, new folder `feedback-relay/`)
- Files: `feedback-relay/src/index.ts` (or `.js`), `feedback-relay/wrangler.toml`, `feedback-relay/README.md` (setup steps), and a unit test of the validation and formatting.
- Secrets (set with `wrangler secret put`, never committed): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- `POST /` only; `OPTIONS` answers CORS preflight. Everything else → 404/405.
- CORS: `Access-Control-Allow-Origin: https://kinojms.github.io` (plus `http://localhost:5173` and `:4173` for local dev). The Android app sends no Origin header and is allowed.
- Validation → 400 on failure:
  - body ≤ 8 KB of JSON,
  - `type` is one of the four values,
  - `message` is 1–2000 characters after trimming,
  - `contact` ≤ 100,
  - `appVersion` ≤ 20,
  - `platform` is one of `Android|iPhone|Web`.
- Forwards with Telegram `sendMessage` (`parse_mode: HTML`, all user text HTML-escaped, `disable_web_page_preview: true`):
  ```
  [FEEDBACK - Gastos.io]
  Type: Bug report
  From: <contact or "—">
  App: v1.4.0 · Android
  Time: 2026-10-17 14:30 (Asia/Manila)

  <message>
  ```
  The time is the Worker's receive time, formatted in Asia/Manila. *(my call)*
- Responses: `200 {"ok":true}` on success. `502` if Telegram fails, without echoing the token or Telegram's error body.
- No rate limiting in v1.4. The free tier allows 100k requests a day, and abuse only spams the owner, who can rotate the URL by redeploying under a new name. *(my call; revisit if spam appears)*

### Owner setup (documented in `feedback-relay/README.md`)
1. In Telegram, talk to @BotFather → `/newbot` → copy the token.
2. Send any message to the new bot, then open `https://api.telegram.org/bot<TOKEN>/getUpdates` and copy `chat.id`.
3. Create a free Cloudflare account. In `feedback-relay/`, run `npx wrangler login`, `npx wrangler secret put TELEGRAM_BOT_TOKEN`, `npx wrangler secret put TELEGRAM_CHAT_ID`, then `npx wrangler deploy`.
4. Put the printed `https://….workers.dev` URL into `config/feedback-url.txt` and release. The owner runs the login and secret steps themselves (they need the owner's accounts); the builder can run `wrangler deploy` once logged in.

## 2. Swipe actions on expense rows

### Where
Every expense row list: the **Today** tab and the **day view** (Days → a day). Both platforms.

### Behavior (decided by owner unless marked)
- Swipe a row **left** to reveal two square action buttons on the right edge, full row height:
  - **Edit**: pen icon, neutral background (`surface2`, icon in `fg`).
  - **Delete**: trash icon, `danger` background, white icon.
  - Icons only on screen. Accessible names are "Edit" and "Delete".
- Edit opens the existing Edit expense sheet. Delete opens the existing confirm ("Delete ₱45.50 · Food?"), then deletes.
- After either action, the row closes.
- **Tapping a row still opens Edit** (owner). Tapping an open row closes it instead of opening Edit. *(my call: avoids surprise)*
- *My calls:*
  - Only one row is open at a time. Opening another, scrolling the list, tapping outside or leaving the screen closes the open one.
  - Swiping right on an open row closes it.
  - Snap rules: release past half of the actions' width (or a fast fling left) → open; otherwise snap back. The row can't be dragged right past closed or more than slightly past fully open (rubber-band ≤ 16 px).
  - Direction lock: a drag only becomes a swipe once horizontal movement exceeds 10 px and is greater than vertical movement. Otherwise it is a scroll, and the row ignores it. On the PWA, rows use `touch-action: pan-y` so vertical scrolling stays native.
  - Action buttons are 72 px (dp) wide each; the row content slides by 144.
  - Animation is about 200 ms. With reduced motion it snaps without animation.
- **Peek hint** (owner): the first time an expense list shows at least one row, the top row slides open on its own, holds about 1 second so Edit and Delete are visible, then closes.
  - It happens once per device, stored as pref `swipe_hint_seen` (not in backups).
  - Touching the list during the peek cancels it and still counts as seen.
  - With reduced motion: the row jumps open, holds, then closes, with no slide.
  - It doesn't run while the guided tour is showing.
- **Tour step** (owner): the guided tour gets a **6th step** on Home.
  - It spotlights the history icon again with the text **"In your history, swipe an expense left to edit or delete it"** and a Done button. *(Copy and staying on Home are my calls. It works even with no expenses yet, and needs no navigation inside the tour.)*
  - Step 5 shows "Next" instead of "Done". The counter becomes "N of 6".
  - `GUIDE_VERSION` becomes 2.
  - Fresh installs see all 6 steps. People who already saw v1 (`guide_seen_version == 1`) see **only the new step** ("6 of 6") once. Show guide in Settings replays all 6. *(my call: don't make returning users redo the whole tour)*
- Accessibility: TalkBack gets custom actions "Edit" and "Delete" on each row. VoiceOver gets the same through visually hidden buttons in the row (same pattern as the Home swipe area).
