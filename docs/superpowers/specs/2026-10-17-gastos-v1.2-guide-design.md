# Gastos.io v1.2 — Guided tour

Date: 2026-10-17
Builds on: v1.1 (`docs/superpowers/specs/2026-10-16-gastos-v1.1-design.md`). Everything there still holds.

## Intent

Teach the Home screen in under a minute: amount, the two swipes, the description box, and where history lives. It should feel like the coach-mark tours other apps use: screen dimmed, one spot lit, short text.

## Goals

- A 5-step coach-mark tour on Home.
- Shown automatically once — on first launch of a fresh install AND on first launch after updating to v1.2 (owner).
- Replayable from Settings → "Show guide" (owner).

## Non-goals

- Tours for other screens (lists, settings, widget).
- Localization of the tour text.

## Anti-goals

- The tour must never save an expense or change data other than what the user deliberately swipes.
- No way to get stuck: every step can be skipped.

## Steps (decided by owner; copy verbatim)

| # | Spotlight target | Text | Advances on |
|---|---|---|---|
| 1 | Numpad (keys + Enter) | "Enter the amount of your expense" | Next |
| 2 | Swipe area | "You can change which payment method you used for this expense" | User swipes left or right once |
| 3 | Swipe area | "Then, you can choose from a set of expense types" | User swipes up or down once |
| 4 | "What did you buy?" text box | "You can also specify what you bought (ex: Jollibee or MTG Cards)" | Next |
| 5 | Expenses history (list) icon in the header | "Finally, keep track of your expenses history here!" | Done |

## Look and behavior

- Full-screen scrim (black ~60–70% opacity) with a rounded-rect cutout around the target (padding ~8dp, corner radius matching the target), plus a soft glow/outline in the theme accent. Animated transition between steps (~250ms). *(default)*
- A text bubble ("coach mark") next to the cutout, placed above or below whichever has more room, using the theme surface/fg colors. Shows the step text, a step counter "2 of 5", "Skip", and "Next" (step 5: "Done"; swipe steps have no Next). *(default)*
- Swipe steps (owner): an animated hand/swipe icon moves across the target (left↔right for step 2, up↕down for step 3) on a loop until the user swipes. The real swipe gesture works inside the cutout; when the user completes one swipe in the right axis, the step advances (~400ms after, so they see the change). A swipe in the wrong axis does nothing. *(timing: default)*
- During the tour, all other input is blocked: numpad, Enter, text box, menu, list icon do nothing. Only the step's swipe (steps 2–3), Next/Done, and Skip work. *(default)*
- Swipes made during the tour really change the payment method / label, same as normal use. *(default)*
- Skip or Done ends the tour and marks it seen. Leaving the app mid-tour ends it and marks it seen (see Resolved details). *(default)*
- Accessibility: the bubble's text is announced; Next/Skip/Done are focusable buttons; on steps 2–3 the existing custom accessibility actions (Next/Previous payment method/label) also count as completing the step. *(default)*
- Respects reduced motion: if animations are off on the phone, the hand icon is shown static with arrows. *(default)*

### Resolved details *(default)*
- **Swipe-step completion:** reuse `HomeSwipe.decide` (same 48dp threshold / dominant axis as normal use). Any decided swipe in the step's axis completes the step, even if nothing changes (e.g. only one active method or label). The "N of 5" counter is fixed.
- **Input routing:** Home receives a tour-mode flag. The overlay consumes touches everywhere except inside the cutout on steps 2–3, where they reach the real swipe area. Next/Skip/Done live in the bubble.
- **Step 1 cutout:** one rounded rect spanning the numpad and the Enter button.
- **Keyboard:** starting the tour clears focus and hides the keyboard; target bounds are re-read after layout.
- **Overlay coverage:** edge-to-edge, positions computed in root coordinates (works with the status bar for step 5).
- **Tour state:** a small `GuideController` held by `AppContainer` (current step or none). Survives configuration changes (rotation, dark-mode toggle, resize). The tour ends and is marked seen on `ON_STOP` (app left) or process death.
- **Replay:** "Show guide" pops back to the Home route and starts the tour via `GuideController`; it does not touch `guideSeenVersion`.
- **Reduced motion:** detected via `Settings.Global.ANIMATOR_DURATION_SCALE == 0`.

## Persistence

- AppPrefs key `guideSeenVersion: Int` (default 0). The app shows the tour on Home when `guideSeenVersion < 1`, then sets it to 1 at Skip/Done/exit. Fresh installs and v1.1 upgrades both have 0, so both see it once. *(default; a version number lets a future release re-show a new tour)*
- Not included in GitHub backups (device preference). *(default)*

## Settings

- New row "Show guide" (in the list of nav rows, above About the dev). Tapping it returns to Home and starts the tour. No confirm popup — it doesn't create/update/delete data. *(default)*
