# Gastos.io v1.1 — Design

Date: 2026-10-16
Builds on: `docs/superpowers/specs/2026-10-16-expenses-tracker-design.md` (v1.0, shipped as release v1.0.0). Everything there still holds unless changed here.
Mockups (approved): https://claude.ai/artifact/PdEAtjcQKDc1wNkXee5gP1

## Intent

Make logging faster and richer without slowing the one-tap entry: pick a label by swiping instead of a dropdown, optionally say what you bought, add notes later, and pick a comfortable color theme.

## Goals

1. Optional "What did you buy?" description on Home, typed or spoken (English or Tagalog).
2. Named color themes, each with light and dark.
3. Notes on an expense, edited in Edit expense.
4. "About the dev" section at the bottom of Settings.
5. Payment methods (Cash, GCash, Maribank, BPI, Maya, BDO), customizable. On Home, swipe left/right to change payment method (screen tints to its brand color); swipe up/down to change the expense label (text only).

## Non-goals

- Description or notes on the widget (widgets have no keyboard).
- Themes on the widget (widget keeps its current always-dark look). *(default)*
- Search/filter by description.
- A manual light/dark override; light/dark keeps following the phone.

## Anti-goals

- Anything that makes adding an expense slower than today. Description stays optional; Enter still needs only an amount.
- Swipe gestures that fire by accident while tapping the numpad or text box.
- Breaking restore of existing v1.0 backups, or losing existing data on upgrade.

## 1. Home screen

Layout top to bottom (see mockup screen 1):
- Header unchanged: date, today's total, list button, overflow menu.
- **Swipe area** (the middle area, between header and text box): payment method name (uppercase, faint ‹ › hints), the expense label as a small pill with faint ˄ ˅ hints, big amount, and page dots (one per active payment method).
- **Text box** with placeholder "What did you buy?".
- Numpad and Enter unchanged.

Behavior (decided by owner):
- **Left/right** swipe changes the **payment method**. The whole screen background tints to the method's color. Order = Payment methods screen order; **wraps around**.
- **Up/down** swipe changes the **expense label** (Food, Transpo…). Only the label text changes — no color change. Order = Labels screen order; **wraps around** (owner decided wrap for swipes).
- Tint is a blend of the method color over the theme background (about 20% light, 26% dark, per mockup), animated briefly. *(blend amounts: default)*
- The label dropdown chip is removed.
- Starts on the last-used label and last-used payment method (both shared with the widget). Swiping updates last-used.
- Amount, swipes, and description can happen in any order. Only the amount is required.
- Enter saves amount + label + payment method + description.
- Tapping outside the text box hides the keyboard (and clears its focus). The numpad keys count as "outside".
- Enter saves amount + current label + description (trimmed; empty → none), clears amount and description, keeps the label. No confirm popup (unchanged rule).
- Toast: "Added ₱45.50 · Jollibee" when there's a description, else "Added ₱45.50 · Food" (as today).

Calls *(default)*:
- A swipe needs a clear drag (threshold ~ 48dp); the dominant axis decides horizontal (method) vs vertical (label), so taps never trigger either. A light haptic tick on each change.
- Toast: "Added ₱185.00 · Jollibee · GCash" (description or label, then method).
- Description max 60 characters; single line; keyboard "Done" closes it.
- Accessibility: custom accessibility actions "Previous/Next payment method" and "Previous/Next label" on the swipe area.

### Payment methods (decided by owner)
- Defaults, in order, with approximate brand colors (no official hex codes found; all recolorable): Cash #77808B (gray), GCash #007DFE (blue), Maribank #FF6A13 (orange), BPI #A6192E (maroon), Maya #00B26B (green), BDO #0033A0 (dark blue). *(hex values: default)*
- Customizable like labels: add, rename, recolor, reorder, delete — each with a confirm popup. New "Payment methods" screen, reached from Settings and the Home overflow menu, built like the Labels screen (same palette swatches plus the six brand colors).
- **Delete keeps history** (owner): a deleted method disappears from swiping and pickers, but past expenses keep showing its name (soft delete / archived flag). At least one active method must remain (delete hidden on the last one). *(default)*
- **Existing v1.0 expenses** get "Cash" on upgrade (owner).
- Names unique among active methods (case-insensitive), trimmed, not blank — same rules/messages as labels.

### Voice input for the description (decided by owner)
- A mic icon sits at the end of the "What did you buy?" box (Home, and the same field in Edit expense).
- Tap it → Android's built-in voice prompt (`RecognizerIntent.ACTION_RECOGNIZE_SPEECH`, free-form). The spoken text **replaces** the box content (trimmed, cut to 60 chars). Cancel or no match leaves the box unchanged. *(replace vs. append: default)*
- Uses the system recognizer, so the app needs no microphone permission. *(default)*
- Languages: English and Tagalog (owner). Settings → "Voice language": **English (Philippines)** `en-PH` (default) or **Tagalog** `fil-PH`, passed as `EXTRA_LANGUAGE`. *(a setting rather than auto-detect: default — the system prompt doesn't reliably auto-detect between the two)* Changing it confirms like other settings.
- If the phone has no speech recognizer, hide the mic icon.

## 2. Description and notes (data)

- New optional fields on an expense: `description` (≤ 60 chars) and `notes` (≤ 1000 chars). Both nullable; blank saves as null. *(limits: default)*
- New table `payment_methods` (id, name, colorArgb, position, archived) and expense column `paymentMethodId` (non-null after migration).
- Room migration v1 → v2: adds description/notes columns, creates `payment_methods`, inserts the six defaults, and sets every existing expense's `paymentMethodId` to Cash. No other data changes (migration test required). Fresh installs seed the same six.
- Lists (Today, day view): row title = description if present, else label. Subtitle = "Label · GCash · 12:30 PM" when there's a description, else "GCash · 12:30 PM". Small dot uses the method color. *(subtitle format: default)*
- Notes are not shown in lists; only in Edit expense.

### Month tab (decided by owner)
- Adds a "By payment method" breakdown (same bar style) below the existing "By label" one, both for the selected month. Archived methods still appear if they have expenses that month.

### Widget (decided by owner: add a payment-method ticker)
- Top row becomes: label ticker (tap → next label) · payment-method ticker (tap → next method, pill tinted with the method color) · amount. Enter saves with both. Both share last-used values with Home. Widget otherwise unchanged (no description, always dark). *(exact arrangement: default; keep the 4×3 default and readable text)*

## 3. Edit expense

- Adds a "What did you buy?" field (same 60-char limit), a "Payment" picker (active methods, plus the expense's current method if archived), and a large multi-line "Notes" box with placeholder "Add notes…".
- Save and Delete keep their confirm popups. The save confirm text stays "Save changes to ₱45.50 · Transpo?".

## 4. Export

- Columns become: Date, Time, Label, Payment, Description, Amount, Notes (owner: description and notes both included). *(column order: default; Notes last since it's long)*
- CSV: same escaping rules as v1.0 (notes may contain commas, quotes, newlines).
- XLSX: total row SUMs the Amount column (now column F); Notes column width capped (e.g. 40) with wrap text. Monthly XLSX keeps "By label" and adds a "By payment" sheet (same layout).

## 5. Backup

- Backup JSON gets a `paymentMethods` list (incl. archived) and `paymentMethodId`, `description`, `notes` on each expense; schema version → 2.
- Restoring a v1 backup still works: the six default methods are created and all its expenses get Cash; description/notes null. Restoring a newer-than-supported version is still refused with the existing message.
- Validation on restore: every expense's `paymentMethodId` must exist; at least one active method.

## 6. Themes (decided by owner: named themes, each with light + dark)

- Light/dark still follows the phone. Theme choice saved in AppPrefs and included in backups? **No** — it's a device preference. *(default)*
